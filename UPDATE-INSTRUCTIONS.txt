EXACT RULE CHANGE FOR A CUSTOM LIVE RULESET
Inside match /users/{userId}, add this function and replace only the old recursive owner read/write block with these lines. Keep all other live rules intact.

      function safeProspectingWrite() {
        let statePath = /databases/$(database)/documents/users/$(userId)/prospecting/state;
        return request.path != statePath
          || !exists(statePath)
          || !get(statePath).data.keys().hasAny(['storageVersion'])
          || (request.resource != null && request.resource.data.keys().hasAll(['storageVersion', 'fields'])
              && request.resource.data.storageVersion in [2, 3]
              && request.resource.data.storageVersion >= get(statePath).data.storageVersion);
      }
      match /{document=**} {
        allow read: if isOwner(userId);
        allow write: if isOwner(userId) && safeProspectingWrite();
      }

WHAT IS PRESERVED
Contacts, contact notes, contact/call interactions, appointments, daily activity, targets, team memberships and leaderboard data are not subject to the MarketPulse expiry policy. Authentication, Firebase project configuration, SMS routing, the iOS Shortcut and Tasker profile are unchanged. The original record IDs and UID separation are preserved.

WHAT EXPIRES
Detailed MarketPulse property events older than 12 calendar months roll off the live cloud snapshot and device archive only after their summaries have been saved. The cutoff uses Sydney's calendar date and includes the cutoff day. This applies to event addresses, guides/prices, agency/agent details and descriptions in the MarketPulse archive. It does not erase information deliberately saved in contact notes or interaction logs.

WHAT REMAINS
A private, small ledger retains a SHA-256 event fingerprint, month, suburb, reported property type and event kind. AGNT derives monthly and lifetime listed/sold/price-update/withdrawn counts from it. No address, price, agent name or free-text description is stored in the permanent ledger. Re-importing the same event ID does not increase the total. Totals represent captured MarketPulse event records, not an independently verified census of unique properties. Separate dated notices are distinct events. Historical fields absent from surviving data are not invented. Prior compact-history aliases are counted when their encoded date/type can be recovered.

RECOVERY AND CLEANUP
A full recovery snapshot of the current cloud state is stored before replacing it. When old device-only property detail is about to expire, a full pre-prune payload is backed up as well. A failed backup stops publication. Recovery copies are kept for at least 30 days. The external backup you export is not automatically deleted.
Cleanup runs on a successful sync while AGNT is open and online. It uses a transaction lease so a concurrent writer must retry, and deletes only age-verified expired recovery manifests and old unreferenced chunks. Current data, unexpired recovery copies, recently uploaded chunks and objects with an unverified age are retained. Cleanup is conservative and limited to 1,000 documents per pass; large backlogs are cleaned over later successful syncs. This is not a new always-running server job.
After a durable IndexedDB checkpoint, duplicate legacy localStorage copies of the large prospecting arrays are removed. A failed device archive read blocks further archive writes until recovery, preserving the existing checkpoint.
Cloud state uses storage version 3. Existing legacy and v2 snapshots remain readable for migration/recovery. The rules block older clients from replacing a migrated v3 head with v2/legacy data. Do not roll back the app or remove the downgrade guard after migration.
